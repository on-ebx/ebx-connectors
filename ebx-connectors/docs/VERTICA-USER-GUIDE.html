1. What the connector does

The dedicated Vertica profile uses the shared bounded JDBC engine for metadata discovery, parameterized reads, controlled writes, catalog inventory, profiling, and samples.

Write boundary: upsert is the shared update-then-insert sequence, not a claim of atomic Vertica MERGE. Bulk write means bounded JDBC batching; the profile does not expose or certify native COPY.

3. Operations

The profile exposes query, get, insert, update, upsert, execute, catalog, profile, and sample. All dynamic values belong in named parameters.

Bounded reads

Cap rows and fetch size, narrow schemas, and avoid unbounded analytical scans from interactive flows.

Controlled batches

Keep batches within the configured ceiling and measure commit, rollback, projection, and resource-pool behavior.

4. Build mappings

SELECT company_id, legal_name, country_code, updated_at
FROM governed.company
WHERE company_id = :companyId
ORDER BY company_id
LIMIT 1

Map only required columns and declare stable keys. For writes, use a dedicated destination table and document segmentation, projections, constraints, duplicate behavior, and the non-atomic update-then-insert boundary.

5. Safe operating sequence

  1. Capture the existing connector and mapping configuration.
  2. Install the approved driver and connect with a read-only identity.
  3. Verify Vertica product/version, database, and intended schema.
  4. Discover one narrow table, then run a bounded preview and one-record parameterized read.
  5. Confirm invalid SQL is recoverable and read-only credentials reject writes.
  6. Simulate the mapping and reconcile fields and counts.
  7. For approved outbound testing, use a dedicated table and low batch size; test insert, update, update-then-insert concurrency, rollback, and independent read-back.
  8. Restore the original configuration and rerun diagnostics.

7. Evidence and acceptance boundary

OFFLINE CONTRACT VERIFIED Exact URL and driver rules, JNDI configuration, numeric bounds, bidirectional operations, capabilities, required vendor dependency, and bulk/upsert caveats have focused tests.

LIVE ACCEPTANCE PENDING A representative Vertica environment must still prove driver compatibility, diagnostics, metadata fidelity, bounded reads, permission denial, batched writes, concurrency behavior, rollback, metrics, and configuration restoration. Native COPY and atomic MERGE are outside this profile’s current claim.
