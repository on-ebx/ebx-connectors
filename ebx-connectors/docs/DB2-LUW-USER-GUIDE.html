1. Certified scope

This profile targets IBM Db2 for Linux, UNIX and Windows (LUW) through the IBM JCC JDBC driver. It does not claim compatibility certification for Db2 for z/OS or Db2 for IBM i; those platforms require separate driver, metadata, SQL and live acceptance evidence.

Inbound

Bounded reads, keyed lookup, catalog, profiling and samples.

Outbound

Insert, update and portable update-then-insert upsert.

Discovery

Schemas, tables, views, columns, keys and JDBC types.

Governance

Separate read and write identities, bounds and auditable mappings.

The IBM JCC driver is licensed and is not implied to be bundled. Confirm its redistribution and deployment terms. A successful generic JDBC connection is not evidence for z/OS or IBM i support.

3. Operations

The connector exposes query, get, insert, update, upsert, execute, catalog, profile, and sample. Named values are bound as prepared-statement parameters. The shared upsert performs UPDATE and then INSERT when no row exists; it is not a native Db2 MERGE and must be evaluated for concurrent writers.

SELECT COMPANY_ID, LEGAL_NAME, COUNTRY_CODE
FROM GOVERNED.COMPANY
WHERE COMPANY_ID = :companyId
FETCH FIRST 1 ROW ONLY

4. Safe operating sequence

  1. Install or configure the approved JCC driver and capture its version and checksum.
  2. Connect using a read-only LUW account and confirm product name, edition and server version.
  3. Discover one approved schema and compare tables, keys and native types with the data contract.
  4. Run a bounded preview and one named-parameter query; prove the read identity cannot write.
  5. Simulate mappings and reconcile proposed counts.
  6. For an approved write, use a dedicated table, validate affected rows and rollback, then perform independent read-back.
  7. Restore the baseline configuration and retain logs, run ID and metrics.

6. Evidence status

OFFLINE CONTRACT VERIFIED Automated tests cover LUW identity, URL and driver validation, safe bounds, JNDI, descriptor capabilities, dependency disclosure, operations and platform boundary.

LIVE ACCEPTANCE PENDING A supported Db2 LUW environment must still prove TLS, metadata discovery, bounded reads, denied writes, controlled write/upsert, rollback and restoration. Db2 for z/OS and IBM i require their own acceptance track.
