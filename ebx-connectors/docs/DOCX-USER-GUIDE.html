Word documents (.docx)

Bounded, read-only text extraction for governed file connectors.

Evidence: deterministic extraction and hostile-package limits verified

1. Scope

The DOCX codec extracts text from the main body of an OOXML Word document. It is intended for inbound mappings through existing file transports such as SFTP, FTP/FTPS, S3, Azure Blob, and Google Cloud Storage.

Extraction is read-only. The module does not create or modify Word documents, render pages, run fields, evaluate embedded content, or contact URLs referenced by a document.

2. Configure the file operation

  1. Open the file connector from the Data connector perspective.
  2. Set its format explicitly to docx. Filename extension alone does not enable document extraction.
  3. Set bounded max.bytes and max.rows values appropriate for the mapping.
  4. Use an inbound mapping to map the returned chunk fields into EBX.

3. Extraction output

Each row is a bounded text chunk with a kind of HEADING, PARAGRAPH, or TABLE_CELL. Provenance identifies word/document.xml, its body block, table row and cell where applicable, and UTF-16 text offsets. Page numbers are deliberately unavailable because extraction does not perform Word layout.

The result reports truncated=true when the configured row limit stops extraction.

4. Safety boundaries

Only one valid DOCX main document relationship and content type are accepted. Package bytes, expanded bytes, entries, XML depth, XML nodes, extracted text, styles, chunks, and result rows are bounded.

Legacy .doc, encrypted documents, macros, ActiveX, embedded objects, external relationships, alternate chunks, fields, drawings, revisions, content controls, nested tables, unsafe ZIP paths, DTDs, external entities, and XInclude are rejected. Headers and footers may be listed as omitted provenance but are not extracted.

5. Acceptance

OFFLINE VERIFIED Paragraph, heading, table-cell and chunk provenance; explicit routing; row and byte bounds; and rejection of external, active, macro, traversal and unsafe XML content.

LIVE ACCEPTANCE Validate representative approved customer documents through the selected remote file transport and mapping before production use.
