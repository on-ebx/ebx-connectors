Apache Spark SQL

Read-only governed SQL through a separately managed Spark Thrift Server endpoint.

Run against Apache Hive 4.0.1 (HiveServer2) with the Apache driver; never against a Spark Thrift Server
On this page1. Scope2. Configure3. Boundaries

1. Scope

The profile reuses the bounded JDBC engine against a Spark Thrift Server / HiveServer2 endpoint. It exposes read-only query, catalog, profile, and sample operations.

2. Configure

Use jdbc:hive2://…;ssl=true or a container-managed JNDI DataSource. Install a separately reviewed Java 8-compatible Hive JDBC dependency closure; the module does not bundle it. Store credentials outside the URL.

3. Boundaries

Only a single read-only SELECT and bounded metadata/statistics operations are exposed. Writes, arbitrary execute, stored procedures, job submission, Spark Connect, streaming, session administration, and an embedded Spark runtime are excluded. Live acceptance must validate the exact Spark/Hive driver matrix, TLS, authentication, catalogs, cancellation, query ceilings, and audit.

The profile shares its rules with the Cloudera Hive and Impala connections: no read-only connection mode and no rollback are required from the driver (the Apache Hive driver refuses both; before this, a query, a preview and a discovery could not return), a TRANSFORM … USING statement is refused, and the table prefix HiveServer2 puts on the columns of a SELECT * is dropped. A URL that asks for Kerberos is reported at validation.
