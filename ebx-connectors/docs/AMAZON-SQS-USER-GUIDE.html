Amazon SQS

Send and receive bounded queue messages with shared hardened AWS credentials and explicit acknowledgement.

1. Safe queue semantics

Receive and peek never delete a message. Only the explicit ack operation deletes by receipt handle. Receive is bounded to 1–10 messages, long polling to 0–20 seconds, and visibility to 0–43200 seconds.

A received message can become temporarily invisible. Persist processing evidence before acknowledging it; never acknowledge a failed mapping.

3. Operations

send sends one message up to 256 KiB. receive performs a bounded receive without deletion. peek requests one immediately visible message with zero wait and zero visibility timeout. ack explicitly deletes using receiptHandle.

4. Safe run

  1. Use a least-privilege queue policy.
  2. Send a unique fixture message.
  3. Receive without acknowledgement and verify redelivery.
  4. Map and independently verify the outcome.
  5. Acknowledge only the successfully processed receipt handle.
  6. Retain message ID, execution ID, metrics, and cleanup evidence.
