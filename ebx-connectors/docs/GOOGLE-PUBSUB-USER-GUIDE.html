Google Cloud Pub/Sub

Publish bounded messages, pull without automatic acknowledgement, acknowledge explicitly, and discover project topics and subscriptions.

1. Configure

SettingGuidance
projectGoogle Cloud project ID containing the topics and subscriptions.
AuthenticationService-account JSON/file or an encrypted bearer access token; grant only required Pub/Sub roles.
EndpointDefaults to https://pubsub.googleapis.com/v1. Non-official remote endpoints are refused; localhost is accepted only for offline fixtures.
NetworkAllow-list the official host and use normal TLS trust and hostname verification.

2. Operations

OperationContract
publishOne topic and one payload, base64 encoded; maximum 10 MiB before API overhead.
pullOne subscription, 1–1,000 messages; returns ack IDs and never acknowledges automatically.
ackExplicit subscription plus 1–1,000 comma-separated ack IDs.
topicsBounded topic discovery with page size/token.
subscriptionsBounded subscription discovery with page size/token.

3. Delivery safety

Pull is not acknowledgement. Persist or complete the governed work first, then call ack with the exact ack ID. If execution fails or the deadline expires, Pub/Sub may redeliver; mappings and downstream writes must be idempotent.

The connector refuses redirects while carrying authorization, limits response bodies to 1 MiB, returns status-only HTTP failures, and never includes bearer tokens or remote error bodies in its messages.

4. Safe operating sequence

  1. Use a test project and least-privilege identity.
  2. Discover the intended topic and subscription.
  3. Publish a uniquely identified test message.
  4. Pull one message and verify payload, message ID, attributes, and ack ID.
  5. Prove no acknowledge call occurred during pull.
  6. Complete the governed action, then explicitly acknowledge its ack ID.
  7. Test redelivery and duplicate-safe handling before increasing bounds.
