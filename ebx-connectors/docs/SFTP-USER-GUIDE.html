1. What the connector does

The SFTP connector provides file-object discovery and preview over SSH. Use it for inbound delimited files and controlled outbound file drops where the mapping defines the document shape.

Inbound

List a bounded directory, select a file, preview its fields, and map rows into EBX.

Outbound

Serialize approved EBX records and upload to an agreed path/name.

Authentication

Basic username/password or SSH private key, with host-key verification.

Isolation

Restrict the SFTP account to its intended root and apply archive/error-file conventions.

2. Configure

SettingGuidance
Base URLsftp://host:22 with the approved host and port.
CredentialsDedicated account; use encrypted password or the connector’s privateKey file.
knownHostsPath of a known_hosts file on the EBX server that lists this host. Required, unless hostKey is set: without either the connector refuses to connect.
hostKeyThe public key of the server, as ssh-keyscan <host> prints it (several keys allowed). Used instead of knownHosts.
strictHostKeyLeave unset. false connects without verifying the server: test servers only.
Root/pathRestrict the account and mappings to the agreed inbound/outbound directories.
Do not disable host-key verification as a routine fix. Validate and deploy the server key through the approved trust process.

3. Build file mappings

Use discovery/preview to select the remote object and derive fields. For CSV, define delimiter, header behavior, encoding, item path, record key, and create/update policy explicitly. Bound listings and row counts.

Fixture root: upload/
Inbound file: company_source.csv
Expected controls: bounded listing · header/field discovery · deterministic rows

Outbound delivery

Use a deterministic file name or collision policy. Prefer upload-to-temporary-name followed by an atomic rename when the receiving system must not see partial files. Never overwrite an existing business file unless that behavior is explicitly approved.

4. Safe operating sequence

  1. Record the existing connector endpoint, auth mode, host-key settings, and mappings.
  2. Run diagnostics and a bounded listing inside the restricted root.
  3. Preview company_source.csv; verify encoding, header, five fields, and deterministic rows.
  4. Simulate the inbound mapping and review record keys and proposed changes.
  5. For outbound, write one tagged file to a disposable path and read it back independently.
  6. Request a missing file and require recoverable feedback with no EBX changes.
  7. Archive or remove only the tagged fixture according to policy, then restore connector configuration.
