H2 Database

Use the dedicated H2 connector for bounded JDBC discovery, parameterized reads, and controlled transactional writes.

Evidence state: isolated fixture verified; EBX acceptance pending

1. Scope and safety

H2 uses the shared JDBC operation set. It is useful for controlled integrations and test environments, but the connector must never be pointed casually at the EBX repository database.

Isolation requirement: use a separate H2 database and account. The acceptance fixture is an independent TCP server, not the EBX repository.

3. Operations and mappings

The connector provides query, get, insert, update, upsert, execute, catalog, profile, and sample. Use named parameters such as :companyId; do not concatenate values into SQL.

SELECT COMPANY_ID, LEGAL_NAME, COUNTRY_CODE, LEI, UPDATED_AT
FROM PUBLIC.COMPANY_SOURCE
WHERE COMPANY_ID = :companyId
LIMIT 1

4. Safe operating sequence

  1. Preserve the existing connector configuration.
  2. Point the existing record to the isolated fixture only during the approved window.
  3. Run the diagnostic and discover PUBLIC.COMPANY_SOURCE with five columns.
  4. Run a three-row bounded preview and a one-row parameterized query.
  5. Confirm invalid SQL returns a SQLState-bearing recoverable error.
  6. Confirm the read-only user cannot write.
  7. Simulate the existing mapping, inspect counts and rules, then restore the original configuration.
