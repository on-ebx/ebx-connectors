CMIS Repository

Vendor-neutral CMIS 1.1 Browser Binding discovery, browsing, content, and controlled writes.

Evidence: loopback Browser Binding fixture verified; live repository acceptance pending
On this page1. Configure2. Operations3. Security4. Acceptance

1. Configure

Use the HTTPS Browser Binding service URL and Basic or bearer authentication. Credentials must not be embedded in the URL. The endpoint must pass the platform egress allow-list.

2. Operations

repositories, children, and object expose bounded metadata. content returns at most 10 MiB as base64. createDocument sends one bounded multipart document; deleteObject removes one selected object. Folder traversal is limited to 500 results per call and an offset ceiling of 100,000.

3. Security

HTTPS is mandatory outside the isolated fixture. Redirects are refused by the shared HTTP client. Error bodies and credentials are not returned. Recursive delete, ACL mutation, checkout/check-in, version deletion, and arbitrary CMIS actions are not exposed.

4. Acceptance

OFFLINE VERIFIED Browser selectors, bounds, content encoding, multipart creation, Basic authentication, and TLS policy.

LIVE ACCEPTANCE Validate vendor Browser Binding paths, repository permissions, versioning policy, content disposition, cleanup, and audit evidence.
