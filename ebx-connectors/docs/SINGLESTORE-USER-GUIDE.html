SingleStore Database

Discover MySQL-compatible schemas, execute bounded prepared SQL, and transfer governed records with transaction-aware JDBC operations.

1. What the connector does

The SingleStore profile uses the shared bounded JDBC engine with MySQL-compatible connection and driver conventions. SingleStore’s distributed tables and SQL behavior remain deployment-specific and require explicit acceptance evidence.

Inbound

Run prepared queries and import bounded result sets.

Outbound

Insert, update, or upsert approved records transactionally.

Discovery

Inspect databases, tables, views, columns, keys, and types.

Safety

Separate read and write identities, cap batches, and prove results independently.

MySQL wire compatibility does not guarantee identical SQL or metadata behavior. Validate shard/unique keys, columnstore or rowstore constraints, and upsert semantics on the target SingleStore release.

3. Operations

The profile exposes query, get, insert, update, upsert, execute, catalog, profile, and sample. Use named inputs and explicit keys; never concatenate user-controlled values into SQL.

4. Build mappings

SELECT company_id, legal_name, country_code, updated_at
FROM governed_source.company
WHERE company_id = :companyId
ORDER BY company_id
LIMIT 1

Expose only required columns and preserve stable business keys. For outbound mappings, document the destination table’s shard key, unique key, storage type, and expected duplicate behavior.

5. Safe operating sequence

  1. Preserve the existing connector and mapping values.
  2. Connect with a read-only identity and confirm SingleStore product/version metadata.
  3. Discover one database/table and compare its keys and types with the mapping contract.
  4. Run a small preview and a one-record named-parameter read.
  5. Confirm invalid SQL is recoverable and the read-only identity rejects writes.
  6. Simulate the mapping and reconcile row counts.
  7. For an approved write, validate shard/unique keys, affected rows, rollback, duplicate handling, and independent read-back.
  8. Restore the original configuration and rerun diagnostics.

7. Evidence status

CONTRACT VERIFIED The dedicated profile is expected to enforce MySQL-compatible URL/driver defaults and shared JDBC safety bounds through automated connector tests.

LIVE ACCEPTANCE PENDING A representative SingleStore deployment must still prove metadata discovery, bounded reads, permission denial, distributed-table writes where authorized, duplicate handling, rollback, metrics, and configuration restoration.
