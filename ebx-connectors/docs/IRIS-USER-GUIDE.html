1. Scope and compatibility

IRIS is the canonical connector type and label. It uses the shared bounded JDBC engine for discovery, reads, writes, cataloging, profiling, and sampling.

Caché compatibility: legacy jdbc:Cache: URLs are accepted for compatible deployments, but this does not certify every Caché release or driver. New configurations should use IRIS and jdbc:IRIS:.

3. Operations

The profile exposes query, get, insert, update, upsert, execute, catalog, profile, and sample. Values are bound through named parameters; never concatenate user-controlled input into SQL.

4. Build mappings

SELECT CompanyId, LegalName, CountryCode, UpdatedAt
FROM Governed.Company
WHERE CompanyId = :companyId
ORDER BY CompanyId
FETCH FIRST 1 ROW ONLY

Discover the target first, map only required columns, and use explicit stable keys. Keep inbound source objects separate from outbound governed-output tables and qualify schema names when ambiguity is possible.

5. Safe operating sequence

  1. Record the existing connector and mapping configuration.
  2. Install the approved driver and connect with a read-only identity.
  3. Verify product/version and intended namespace, then discover one narrow schema.
  4. Run a bounded preview and a one-record named-parameter query.
  5. Confirm invalid SQL is recoverable and read-only credentials reject writes.
  6. Simulate the mapping and reconcile fields and counts.
  7. For an approved outbound flow, write to a dedicated destination table, validate affected rows and rollback, and read back independently.
  8. Restore the original configuration and rerun diagnostics.

7. Evidence and acceptance boundary

OFFLINE CONTRACT VERIFIED Canonical identity, IRIS and legacy Caché URL acceptance, unrelated URL/driver rejection, numeric bounds, JNDI configuration, bidirectional operations, capabilities, and required driver metadata have focused tests.

LIVE ACCEPTANCE PENDING A representative IRIS environment must still prove the installed driver, connection diagnostic, metadata fidelity, bounded reads, permission denial, approved writes, rollback, metrics, and configuration restoration. Legacy Caché releases require their own compatibility evidence.
