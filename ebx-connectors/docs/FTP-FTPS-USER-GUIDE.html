FTP / FTPS

Exchange bounded governed files over explicit or implicit TLS-protected FTP.

Evidence state: offline transport contract verified; live server acceptance pending
On this page1. Modes2. Configure3. Operations4. Safe run5. Evidence

1. Choose the transport deliberately

Explicit FTPS

ftps://host:21. Starts as FTP, then requires AUTH TLS and a protected data channel. This is the default when a host has no scheme.

Implicit FTPS

ftps-implicit://host:990. TLS begins immediately on the control connection.

Clear FTP

ftp://host:21 is refused unless allowCleartext=true records an explicit exception.

Not SFTP

SFTP is SSH-based and uses the separate SFTP connector, keys and host-key controls.

2. Configure

SettingGuidance
EndpointPrefer explicit FTPS. JVM trust and hostname verification apply to control and passive data TLS.
CredentialsDedicated least-privilege user/password stored through a supported secret reference.
rootRequired operational boundary for governed paths. Parent traversal, backslashes, absolute escape and FTP command injection are rejected.
max.list1–10,000; keep production listings narrowly scoped.
max.bytes1 byte–100 MiB; default 10 MiB. Reads and writes are rejected above the configured ceiling.
TimeoutsPositive connect and read timeouts apply to control and passive transfers.

3. Operations

list returns bounded metadata, read parses bounded CSV/JSON/NDJSON/XML, and write sends a bounded governed document. Transfers use binary passive mode. The connector does not expose arbitrary FTP commands, active mode, remote delete, rename, or chmod.

4. Safe operating sequence

  1. Confirm the server mode, certificate chain, hostname and passive port policy.
  2. Configure a narrow root and a read-only account.
  3. Test a one-entry metadata listing; do not start with file content.
  4. Read one small non-sensitive fixture and reconcile its checksum and rows.
  5. Prove traversal and writes are denied to the read identity.
  6. For an approved write, use a dedicated directory and independently read back the result.
  7. Retain the run evidence and restore the baseline configuration.
FTP/FTPS uses separate control and data connections. Firewalls must allow the server’s passive range without disabling TLS or hostname verification.

5. Evidence status

OFFLINE CONTRACT VERIFIED Tests cover explicit and implicit FTPS selection, secure defaulting, cleartext opt-in, SFTP separation, listing/byte bounds, rooted paths, traversal and CRLF rejection, and secret-safe failures.

LIVE ACCEPTANCE PENDING Representative servers must prove AUTH TLS, implicit TLS, certificate validation, protected passive data, bounded listing/read/write, timeouts and restoration. Clear FTP should remain disabled.
