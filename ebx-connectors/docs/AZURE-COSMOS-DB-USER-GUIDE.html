Azure Cosmos DB (NoSQL)

Discover databases and containers, execute bounded parameterized queries, and govern partition-scoped item mutations.

Offline REST contract verified; live Azure acceptance pending

Authentication boundary

Use an Entra bearer token or a least-privilege scoped resource token. Account Shared Key signing is deliberately not implemented, and tokens are never included in errors. Configure the HTTPS account endpoint ending in .documents.azure.com.

Operations

databases and containers discover bounded metadata. get performs a point read. query accepts CQL-like Cosmos SQL plus a JSON parameter array, maximum 1–1,000 items, and an opaque continuation token. create, upsert, and delete require an explicit partition key.

Partition and continuation safety

Supply the logical partition-key value as JSON, for example "tenant-1" or a hierarchical array. Never infer it from an item ID. Continuations are opaque, query-specific, capped at 8 KiB, and must not be edited.

Queries without a partition key explicitly enable cross-partition execution and should remain narrowly bounded. Requests are capped at 1 MiB, responses at 2 MiB, authorization-bearing redirects are refused, and remote error bodies are not surfaced.

Acceptance boundary

Offline fixtures cover discovery bounds, parameterized query headers, continuation capture, bearer authentication, partition-key enforcement, and upsert. Live acceptance must prove Entra/resource-token scope, regional endpoint/TLS, RU behavior, consistency, throttling, ETags/concurrency, partition routing, continuation replay, mutations, denial cases, and cleanup. Change feed, bulk executor, stored procedures, attachments, and Shared Key remain out of scope.
