Azure Queue Storage

Send and receive bounded storage-queue messages with explicit pop-receipt acknowledgement.

1. Queue safety

This connector targets Azure Queue Storage REST endpoints. It is not Azure Service Bus and does not claim Service Bus queues, topics, sessions, or settlement semantics.

receive changes visibility but never deletes implicitly. Delete only with explicit ack after successful processing, using the returned message ID and pop receipt.

3. Operations

send sends one XML-escaped message up to 64 KiB. peek reads 1–32 without changing visibility. receive reads 1–32 with visibility 1–604800 seconds and no implicit deletion. ack deletes explicitly with message ID and pop receipt. queues discovers up to 5000 names and returns NextMarker.

4. Safe operating sequence

  1. Use a least-privilege SAS or managed identity policy.
  2. Discover and confirm the intended queue.
  3. Send a unique non-sensitive fixture.
  4. Peek, then receive it and capture message ID and pop receipt.
  5. Process and independently verify the governed result.
  6. Acknowledge only after success; prove failed processing becomes visible again.
  7. Retain metrics, execution evidence, and cleanup proof.
