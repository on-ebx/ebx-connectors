1. What the connector does

The Teradata profile applies vendor-specific URL and driver validation to the shared bounded JDBC engine. Discovery and lightweight governed exchange are in scope; workload design, bulk utilities, temporal features and platform-specific SQL require separate engineering and acceptance.

Inbound

Bounded query, keyed lookup, catalog, profile and sample operations.

Outbound

Prepared insert, update and portable update-then-insert upsert.

Discovery

Databases/schemas, tables, views, columns, keys and JDBC types.

Governance

Least privilege, workload limits, auditable mappings and read-back.

The Teradata JDBC driver is vendor-supplied. Record its exact version and checksum, confirm deployment rights, and certify it against the target Vantage release and session mode.

3. Operations and limitations

The connector exposes query, get, insert, update, upsert, execute, catalog, profile, and sample. Query values are bound through prepared statements and results are bounded.

The shared upsert performs UPDATE followed by INSERT when no row is found. It is not an atomic Teradata MERGE; concurrent writers, fallback tables, primary indexes, identity/generated columns, triggers and affected-row behavior require live validation. FastLoad, MultiLoad, TPT and other Teradata bulk utilities are not provided by this JDBC profile.

SELECT company_id, legal_name, country_code
FROM GOVERNED.company
WHERE company_id = :companyId
QUALIFY ROW_NUMBER() OVER (ORDER BY company_id) = 1

4. Safe operating sequence

  1. Install or configure the approved driver and capture its version/checksum.
  2. Connect with a read-only identity and confirm Vantage version, database and session mode.
  3. Discover one approved scope and reconcile objects, keys and native types.
  4. Run a bounded preview and named-parameter query; prove the account cannot write.
  5. Review the query plan and workload-management classification before increasing bounds.
  6. Simulate mappings and reconcile proposed counts.
  7. For an approved write, use a dedicated table and validate affected rows, rollback and independent read-back.
  8. Restore the baseline and retain logs, query/run IDs and metrics.
