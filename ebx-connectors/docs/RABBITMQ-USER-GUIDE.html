1. What the connector does

The RabbitMQ AMQP 0-9-1 connector supports bounded outbound publish, non-destructive preview, and inbound receive with manual acknowledgement.

Publish

Send one mapped JSON document through an exchange/routing key.

Peek

Inspect a bounded batch and requeue every delivery for safe design-time testing.

Receive

Read a bounded batch and acknowledge deliveries only through the live operation.

Govern

Map message JSON into EBX using explicit record keys and create/update policies.

3. Operations

OperationBehavior
publishPublishes one JSON message using the supplied/default routing key.
peekReads a bounded batch and requeues every delivery; use for preview.
receiveReceives and manually acknowledges a bounded batch; use only for approved live consumption.

Build inbound mappings with peek, then move to receive only after the payload path, record key, error policy, and batch bound have been reviewed.

4. Safe operating sequence

  1. Run diagnostics and confirm the expected broker, virtual host, and queue.
  2. Publish one tagged message and verify it independently in the queue.
  3. Run peek; confirm the message is requeued and the ready count is preserved.
  4. Simulate the inbound mapping and inspect all proposed EBX changes.
  5. Run one bounded receive; confirm successful acknowledgement and zero unacked residue.
  6. Inject malformed JSON only in the disposable error queue and require recoverable error evidence.
  7. Restore the existing connector configuration.
