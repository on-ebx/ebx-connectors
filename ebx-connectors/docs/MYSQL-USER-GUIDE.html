1. What the connector does

The dedicated MySQL connector is backed by the shared bounded JDBC engine and adds MySQL-specific URL, driver, TLS, and descriptor validation.

Use it for inbound queries and table reads, outbound insert/update/upsert, metadata discovery, catalog inventory, profiling, and samples.

2. Configure

SettingExample / guidance
JDBC URLjdbc:mysql://host:3306/database; the dedicated connector requires the jdbc:mysql:// form unless JNDI is used.
DriverMySQL Connector/J from the supported runtime; do not substitute an unrelated JDBC driver.
CredentialsDedicated user/password in encrypted fields.
TLSUse verified TLS settings required by the environment. Do not disable certificate verification for convenience.
BoundsSet max.rows, fetch.size, and batch.size.
The disposable lab runs on localhost:13306; that port, password, and any relaxed local settings are not production defaults.

3. Operations and mapping

Available operations are query, get, insert, update, upsert, execute, catalog, profile, and sample. Use :named parameters and explicit keys.

SELECT company_id, legal_name, country_code, lei, updated_at
FROM company_source
WHERE company_id = :companyId
LIMIT 1

4. Safe operating sequence

  1. Capture the original existing connector and mapping values.
  2. Run the diagnostic and confirm the intended server/database.
  3. Discover company_source and its five expected columns.
  4. Run bounded and parameterized reads; reconcile the deterministic three-row fixture.
  5. Run invalid SQL and require clear, recoverable feedback.
  6. Confirm the read-only fixture account rejects writes.
  7. Simulate the existing mapping; if an outbound flow is approved, grant only its destination-table operations.
  8. Restore configuration and rerun the diagnostic.
