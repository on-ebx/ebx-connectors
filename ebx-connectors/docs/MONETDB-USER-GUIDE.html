MonetDB

Discover analytical schemas, run bounded parameterized SQL, and transfer governed records through the shared JDBC engine.

1. What the connector does

The dedicated MonetDB profile uses the official Java 8 JDBC driver contract for bounded discovery, reads, controlled writes, catalog inventory, profiling, and samples.

Client-file boundary: MonetDB can request client-side files for COPY … ON CLIENT, but this connector exposes no upload-handler callback. Such requests remain blocked by default and are outside the accepted operation set.

3. Operations

Available operations are query, get, insert, update, upsert, execute, catalog, profile, and sample. Use named parameters and bounded results. The shared upsert is update-then-insert, not a claim of atomic database-native merge.

SELECT company_id, legal_name, country_code
FROM governed.company
WHERE company_id = :companyId
ORDER BY company_id
LIMIT 1

4. Safe operating sequence

  1. Install the approved Java 8 driver and preserve existing configuration.
  2. Connect read-only and verify server/database metadata.
  3. Discover one schema and run a small preview plus one-record parameterized read.
  4. Confirm invalid SQL is recoverable and writes are denied.
  5. Simulate mappings and reconcile fields and counts.
  6. For approved writes, use a dedicated table, small batches, explicit keys, rollback, and independent read-back.
  7. Restore configuration and rerun diagnostics.

5. JDBC limitations

AreaBoundary
TransactionsMonetDB documents fully serializable isolation; alternative isolation levels require warning checks.
SavepointsNot supported by the documented JDBC surface; do not design recovery around them.
Result setsUpdateable result sets and several advanced JDBC types/interfaces are unavailable.
Client COPYNo upload/download handler is registered; client filesystem transfer is deliberately unavailable.
TLS URLjdbc:monetdbs:// requires driver 12.0 or newer and normal certificate/trust validation.
